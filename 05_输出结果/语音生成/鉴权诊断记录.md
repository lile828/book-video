## 二、完整诊断链路

### 第 1 把 Key（ark- 前缀）

```bash
GET https://ark.cn-beijing.volces.com/api/v3/models
→ 200，返回 138 个模型（文本/视觉/视频类）
```

结论：Key 本身有效，但**列表里没有任何音频模型**（`seed-audio` / `tts` / `speech` 全无）。
注：方舟的 `/models` 只返回预置模型，**自定义接入点（endpoint）不在此列表**，所以这不能完全排除可能性。

对 `openspeech.bytedance.com/api/v3/tts/create` 调用：
```json
{"code":45000010,"message":"Invalid X-Api-Key"}
```
→ **两个产品线的 Key 不通用**，这是预期的。

对方舟音频端点探测 6 个候选路径，**全部 404**：
```
/api/v3/audio/speech              404
/api/v3/contents/audio/speech      404
/api/v3/audio/generations          404
/api/v3/contents/audio/generations 404
/api/v3/tts/create                 404
/api/v3/audio/speech/tts           404
```

### 第 2 把 Key（UUID 格式）

对文档原始端点调用：
```json
POST https://openspeech.bytedance.com/api/v3/tts/create
→ 403 {"code":45000030,
        "message":"[resource_id=volc.service_type.10074] requested resource not granted"}
```

**关键判断**：
- 从 401 变成 403 → **鉴权已通过**，Key 是有效的
- `resource_id=volc.service_type.10074` → 请求**正确路由到了音频生成服务**，model 映射也对
- 403 而非 400 → 不是参数问题，是**授权问题**

模型名对照测试：

| model | 返回 |
|---|---|
| `seed-audio-1.0` | `resource_id=volc.service_type.10074` → 映射成功，**但未授权** |
| `seed-tts-1.0` | `fail to convert model to resource_id` → 模型名无效 |
| `volc.service_type.10074` | `fail to convert model to resource_id` → 模型名无效 |

补 `X-Api-Resource-Id` 头 → 同样 403，无帮助。

老版端点 `/api/v1/tts` 探测：
```json
POST https://openspeech.bytedance.com/api/v1/tts
→ 400 "Missing required: app.cluster"     ← 路由通，是参数问题
→ 补全 cluster 后
→ 403 "[resource_id=tts.sync.level1] requested resource not granted"  ← 同样未授权
```

## 五、备选方案（若不便开通音频生成）

老版 TTS 端点 `/api/v1/tts` 的路由是通的，只要开通 **标准语音合成（tts.sync.level1）** 也能出音，
但**不支持**：
- seed-audio-1.0 的自然语言时间轴控制（停顿/语速曲线只能靠 SSML 或分段拼接）
- 参考音频 / 参考图片音色复刻
- 字级字幕时间戳

本项目要靠时间轴控制做 9 段节奏 + 逐句时间轴，**强烈建议开通音频生成**。
若只能开通标准 TTS，脚本需改为「分段多次合成 + 本地拼接」，逐句时间轴要靠本地音频长度推算。
